# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Shooter Shop Simulator" — a shooting-range / gun-shop management sim (buy stock from suppliers, keep a warehouse, sell guns and ammo, run a shooting range), built on Akila FPS Framework. Current goal: an MVP with ~30 minutes of gameplay. Unity **6000.3.12f1** (Unity 6.3) project using **URP 17.3** and the new **Input System** (`Assets/InputSystem_Actions.inputactions`). Game code lives in `Assets/_Project` (`Scripts/` = `ShooterShop.Runtime` asmdef, `Configs/` = SO assets, `Editor/` = `ShooterShop.Editor`).

## Building / running

There are no CLI build scripts. Work happens in the Unity Editor. The `.sln` / `.csproj` files at the root are regenerated by Unity — never edit them by hand. Prefer driving a running Editor via the Unity CLI / MCP (see the `unity:unity-cli` skill) over hand-editing `.unity`, `.prefab`, or `.asset` YAML.

`com.unity.test-framework` is installed but no project tests exist yet.

## Code layout

- `Assets/ThirdParty/Akila/FPS Framework/` — **primary framework we build on**: third-party **Akila FPS Framework** (assembly `Akila.FPSFramework`, ~240 scripts): character controller, weapons, animation system (see `PAExample` script for how it works), audio, input, settings management, UI. Its own readme warns: **do not use the default scenes/prefabs directly — duplicate them first**, since the framework's files may change on update.
- `Assets/ThirdParty/Akila/FPS Framework Pro/` — Pro add-on: **Mirror multiplayer** layer (`Network*` wrappers over core classes, `FPSFNetworkManager`, game modes). No asmdef, so it compiles into `Assembly-CSharp`.
- `Assets/Mirror/` — Mirror networking (used by Akila Pro), including many example scenes.
- **Scenes:** Akila `Main Menu` (entry point, menu) and **`Demo` (main game scene)**. `Loading` and Pro `Multiplayer Demo` are Akila samples.
- `Packages/com.rimi-kun.aetheria/` — embedded local package (assemblies `Aetheria.Runtime` / `Aetheria.Editor`): water (buoyancy, GPU) and volumetric fog rendering.
- `Packages/com.unity.render-pipelines.*` — **embedded (locally modified) copies** of URP/Core. Avoid changing them unless intentional.
- `Assets/TutorialInfo`, `Assets/Readme.asset` — Unity template boilerplate, safe to ignore.

**Akila is a fork.** We modify its scripts directly to fit our architecture (VContainer, UniTask, no lifecycle callbacks) and do not take upstream updates. New game-specific code goes in `Assets/_Project`. Code in `Assembly-CSharp` can reference `Akila.FPSFramework`; an asmdef for new game code must list `Akila.FPSFramework` explicitly.

## Architecture rules (mandatory for all game code)

1. **DI via VContainer.** Wire dependencies through `LifetimeScope`s and constructor/`[Inject]` injection, not singletons or scene lookups.
2. **No `GetComponent`** (or its variants / `FindObjectOfType`), or as little as possible. Pass references through DI or serialized fields.
3. **Avoid MonoBehaviour lifecycle callbacks** (`Awake`, `Start`, `OnEnable`, `OnDisable`, `Update`) so that no code runs outside our control. Use VContainer entry points (`IStartable`, `IInitializable`, `ITickable`, `IDisposable`) and explicit init calls instead.
4. **Async via UniTask**, not coroutines or `Task`.
5. **No code comments.** Code should explain itself through naming.
6. **Use design patterns sensibly**, only where they actually help.
7. **Prefer DTOs / data in ScriptableObjects.** Configs and data live in SOs, not in hardcoded values or MonoBehaviour fields.
8. **Lay out SO and other config inspectors with Odin Inspector** attributes (installed at `Assets/Plugins/Sirenix`).
9. **OOP, applied carefully.** Prefer composition, keep inheritance shallow.
10. **Follow SOLID.**
11. **UI uses MVP.** View = a passive MonoBehaviour, Presenter = a plain C# class wired by VContainer, Model = data/state.
12. **KISS.** Don't over-engineer. Pick the simplest design that fits.
13. **DRY.** Build reusable components and flexible abstractions instead of duplicating logic.

VContainer (`jp.hadashikick.vcontainer` 1.19.0) and UniTask (`com.cysharp.unitask` 2.5.11) are installed as git-URL packages in `Packages/manifest.json`. Game asmdefs must reference `VContainer` and `UniTask`.

## Scopes and networking

The game is always a Mirror session: **solo = host with `NetworkServer.listen = false`**, co-op = open host plus LAN discovery / direct IP (KCP, port 7777). Steam is planned later and only swaps the transport.

- **`ProjectLifetimeScope`** (`Assets/_Project/Prefabs/ProjectLifetimeScope.prefab`) is the VContainer root scope, set in `Configs/VContainerSettings.asset` (preloaded asset), and it lives for the whole app. Its child `ShopNetworkManager` (unpacked from Akila's Network Manager; raises `ClientStopped`, `dontDestroyOnLoad = false`, offline = `Main Menu`, online = `Demo`, player = `Player Network`) and `NetworkDiscovery` are registered here together with `INetworkSession` and `ILanDiscovery`.
- **Loading screen** = Akila's `Loading` scene used as an overlay. On first `ILoadingScreen.ShowAsync()` it is loaded additively and its `LoadingLifetimeScope` attaches the Akila `LoadingScreen` (DDOL) to `SceneLoadingScreen`. `NetworkSession` shows it before every solo / host / join / leave. `GameLoadingCloser` hides it once the local player has spawned, and `MainMenuPresenter` hides it on start or when the session stops. The hide waits for Akila's `postLoadDelay`.
- **`MenuLifetimeScope`** (`Main Menu` scene) runs the MVP menu `MainMenuView` / `MainMenuPresenter`: Solo, Host, Join by IP and a list of LAN servers.
- **`GameLifetimeScope`** (`Demo` scene) holds configs, `Wallet` / `Warehouse` and `ShopNetworkState`. `OfflineSessionStarter` starts solo when you press Play straight from `Demo`.
- **Shop state is server-authoritative.** `IWallet` / `IWarehouse` are the server-side model and only the host changes them. Gameplay and UI on every peer read state through **`IShopState`** (SyncVar / SyncDictionary keyed by `ProductCatalog` index) and change it through **`IShopCommands`** (direct call on the host, `[Command]` on clients).
- **Gameplay UI** lives on the `Shop UI` canvas in `Demo`: the `PurchaseTerminal` (an `IInteractable`, opened with E through Akila's `InteractionsManager`) drives `PurchaseTerminalView` / `PurchaseTerminalPresenter`, and `MoneyHudView` shows the balance. Any UI that needs the cursor takes `IPlayerInputLock`, which toggles `FPSFrameworkCore.IsInputActive` and the cursor and is reference-counted per owner.
- Akila HUD (pause, ammo, hitmarker) is spawned by `Game Manager` through its `uIManager` field, which `Demo` points at Pro's `HUD Variant`.
- `Demo` uses Akila Pro's `Game Manager Variant` with `GameModer` / `GameModerUI` removed (no deathmatch) and `NetworkStartPosition` on the spawn points.

Vendor patches: Mirror `NetworkManager.StopServer/StopClient` only move a **root** NetworkManager out of DDOL (ours is parented to the root scope). Akila Pro `NetworkActor` null-guards `GameModer.Instance`. `PauseMenu` ignores Esc while input is locked. `AutoLeaveSession` stops the session and lets Mirror load the offline scene.

`VContainerSettings.DisableScriptModifier = true` is required: otherwise VContainer overwrites every new `*LifetimeScope.cs` file with its template.

## Conventions

- Always keep `.meta` files paired with their assets (create/move/delete them together) — GUIDs back all scene/prefab references.
- `Library/`, `Temp/`, `Logs/`, `UserSettings/` are generated; don't edit.
- Play Mode tests driven through the Unity CLI need **Run In Background** (or auto-tick). Otherwise an unfocused Editor barely ticks frames and UniTask awaits and scene loads stall. The project keeps Run In Background off.
