# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

"Shooter Shop Simulator" — a shooting-range / gun-shop management sim (buy stock from suppliers, keep a warehouse, sell guns and ammo, run a shooting range), built on Akila FPS Framework. Current goal: an MVP with ~30 minutes of gameplay. Unity **6000.3.12f1** (Unity 6.3) project using **URP 17.3** and the new **Input System** (`Assets/InputSystem_Actions.inputactions`). Game code lives in `Assets/_Project` (`Scripts/` = `ShooterShop.Runtime` asmdef, `Configs/` = SO assets, `Editor/` = `ShooterShop.Editor`).

## Building / running

There are no CLI build scripts. Work happens in the Unity Editor. The `.sln` / `.csproj` files at the root are regenerated by Unity — never edit them by hand. Prefer driving a running Editor via the Unity CLI / MCP (see the `unity:unity-cli` skill) over hand-editing `.unity`, `.prefab`, or `.asset` YAML.

`com.unity.test-framework` is installed but no project tests exist yet.

## Code layout

- `Assets/ThirdParty/Akila/FPS Framework/` — **primary framework we build on**: third-party **Akila FPS Framework** (assembly `Akila.FPSFramework`, ~240 scripts): character controller, weapons, animation system (see `PAExample` script for how it works), audio, input, settings management, UI. Its own readme warns: **do not use the default scenes/prefabs directly — duplicate them first**, since the framework's files may change on update.
- `Assets/ThirdParty/Akila/FPS Framework Pro/` — Pro add-on: **Mirror multiplayer** layer (`Network*` wrappers over core classes, `FPSFNetworkManager`, game modes). No asmdef, so it compiles into `Assembly-CSharp`.
- `Assets/Mirror/` — Mirror networking (used by Akila Pro), including many example scenes.
- **Level:** `GunShop` prefab in `Demo` has two buildings: the shop (floor y≈2, street door at z≈15.5, back counter at z≈6 with the clerk area, player spawn and purchase terminal behind it) and the shooting range (paper targets `Target_1` used by the three lanes), joined by a passage. The old Akila `Enviroment` is disabled. `NavMesh` uses a Volume (y 1.5–5.5) so only the building floor is baked. `ShopLayout` and `ShootingLane` draw labelled gizmos for editing.
- **Scenes:** Akila `Main Menu` (entry point, menu) and **`Demo` (main game scene)**. `Loading` and Pro `Multiplayer Demo` are Akila samples.
- `Packages/com.rimi-kun.aetheria/` — embedded local package (assemblies `Aetheria.Runtime` / `Aetheria.Editor`): water (buoyancy, GPU) and volumetric fog rendering.
- `Packages/com.unity.render-pipelines.*` — **embedded (locally modified) copies** of URP/Core. Avoid changing them unless intentional.
- `Assets/TutorialInfo`, `Assets/Readme.asset` — Unity template boilerplate, safe to ignore.

**Akila is a fork.** We modify its scripts directly to fit our architecture (VContainer, UniTask, no lifecycle callbacks) and do not take upstream updates. New game-specific code goes in `Assets/_Project`. Code in `Assembly-CSharp` can reference `Akila.FPSFramework`; an asmdef for new game code must list `Akila.FPSFramework` explicitly.

## Architecture rules (mandatory for all game code)

1. **DI via VContainer.** Wire dependencies through `LifetimeScope`s and constructor/`[Inject]` injection, not singletons or scene lookups.
2. **No `GetComponent`** (or its variants / `FindObjectOfType`), or as little as possible. Pass references through DI or serialized fields.
3. **Avoid MonoBehaviour lifecycle callbacks** (`Awake`, `Start`, `OnEnable`, `OnDisable`, `Update`) so that no code runs outside our control. Use VContainer entry points (`IStartable`, `IInitializable`, `ITickable`, `IDisposable`) and explicit init calls instead.
4. **Async via UniTask**, not coroutines or `Task`.
5. **No code comments.** Code should explain itself through naming.
6. **Use design patterns sensibly**, only where they actually help.
7. **Prefer DTOs / data in ScriptableObjects.** Configs and data live in SOs, not in hardcoded values or MonoBehaviour fields.
8. **Lay out SO and other config inspectors with Odin Inspector** attributes (installed at `Assets/Plugins/Sirenix`).
9. **OOP, applied carefully.** Prefer composition, keep inheritance shallow.
10. **Follow SOLID.**
11. **UI uses MVP.** View = a passive MonoBehaviour, Presenter = a plain C# class wired by VContainer, Model = data/state.
12. **KISS.** Don't over-engineer. Pick the simplest design that fits.
13. **DRY.** Build reusable components and flexible abstractions instead of duplicating logic.

VContainer (`jp.hadashikick.vcontainer` 1.19.0) and UniTask (`com.cysharp.unitask` 2.5.11) are installed as git-URL packages in `Packages/manifest.json`. Game asmdefs must reference `VContainer` and `UniTask`.

## Scopes and networking

The game is always a Mirror session: **solo = host with `NetworkServer.listen = false`**, co-op = open host plus LAN discovery / direct IP (KCP, port 7777). Steam is planned later and only swaps the transport.

- **`ProjectLifetimeScope`** (`Assets/_Project/Prefabs/ProjectLifetimeScope.prefab`) is the VContainer root scope, set in `Configs/VContainerSettings.asset` (preloaded asset), and it lives for the whole app. Its child `ShopNetworkManager` (unpacked from Akila's Network Manager; raises `ClientStopped`, `dontDestroyOnLoad = false`, offline = `Main Menu`, online = `Demo`, player = `Player Network`) and `NetworkDiscovery` are registered here together with `INetworkSession` and `ILanDiscovery`.
- **Loading screen** = Akila's `Loading` scene used as an overlay. On first `ILoadingScreen.ShowAsync()` it is loaded additively and its `LoadingLifetimeScope` attaches the Akila `LoadingScreen` (DDOL) to `SceneLoadingScreen`. `NetworkSession` shows it before every solo / host / join / leave. `GameLoadingCloser` hides it once the local player has spawned, and `MainMenuPresenter` hides it on start or when the session stops. The hide waits for Akila's `postLoadDelay`.
- **`MenuLifetimeScope`** (`Main Menu` scene) runs the MVP menu `MainMenuView` / `MainMenuPresenter`: Solo, Host, Join by IP and a list of LAN servers.
- **`GameLifetimeScope`** (`Demo` scene) holds configs, `Wallet` / `Warehouse` and `ShopNetworkState`. `OfflineSessionStarter` starts solo when you press Play straight from `Demo`.
- **Shop state is server-authoritative.** `IWallet` / `IWarehouse` are the server-side model and only the host changes them. Gameplay and UI on every peer read state through **`IShopState`** (SyncVar / SyncDictionary keyed by `ProductCatalog` index) and change it through **`IShopCommands`** (direct call on the host, `[Command]` on clients).
- **Gameplay UI** lives on the `Shop UI` canvas in `Demo`: the `PurchaseTerminal` (an `IInteractable`, opened with Interact (F) through Akila's `InteractionsManager`) drives `PurchaseTerminalView` / `PurchaseTerminalPresenter`, and `MoneyHudView` shows the balance. Any UI that needs the cursor takes `IPlayerInputLock`, which toggles `FPSFrameworkCore.IsInputActive` and the cursor and is reference-counted per owner.
- **Physical store:** a purchase pays on the host, adds to `Warehouse` totals and `DeliveryService` spawns `DeliveryBox`es (`StoreConfig`, `ProductConfig.UnitsPerBox`) at `StoreLayout.DeliveryPoint` on the street after a delay. Starting and saved stock arrive the same way (`StartingStockDelivery`). Players pick a box up with the Akila Interact key (F on keyboard) (`CarryService` makes it follow the carrier's `CameraRoot/CameraPivot` on every peer), drop it with G (raycast to the floor, rest pose synced), and press Interact on a `ProductStand` to put one unit per press into a free slot. A stand only accepts its `ProductCategory` list and shows `ProductConfig.ShelfModel` copies. Customers go Browsing to a stand that has their product, take what is there (`ServerTake`), queue and pay; `Warehouse` is reduced only at payment. If they leave unpaid, the items go back to the stand, or into a box at delivery when the stand is full. Boxes and customers are spawned on clients through `InjectedPrefabRegistrar`, and stands are injected by a build callback in `GameLifetimeScope`.
- **Interaction feedback:** Akila's `InteractionsManager` only finds colliders on layer 15 `Iteractable`, so every interactable lives on that layer. It skips interactables whose prompt is empty (fork patch) and shows only the Keyboard&Mouse binding. Highlighting the current interactable toggles an `InteractableOutline` (inverted-hull URP shader `ShooterShop/Interactable Outline`, `Art/Materials/InteractableOutline.mat`). Item motion uses **PrimeTween** (npm scoped registry, 1.4.11) through `ItemAnimator` + `FeedbackConfig`: units fly into stand slots from the nearby carried box, taken items shrink away, boxes pop in, punch on pickup and bounce when dropped.
- **Customers** run on the host only. `CustomerDirector` spawns them from `CustomerConfig`, walks them over the baked `NavMesh` (`ShopLayout`: Entrance, Exit and `QueuePoints`, where [0] is the register at the back counter of the shop building and the rest form a line toward the street door), only the customer at the register can be served, the line advances when they leave, checks patience and despawns them, and handles `TrySell` / `Dismiss`. `Customer` is a `NetworkBehaviour` + `IInteractable` that syncs its request and state; its NavMeshAgent runs only on the server and `NetworkTransformReliable` moves the client copies. Clients instantiate customers through VContainer via `CustomerSpawnRegistrar` (`NetworkClient.RegisterPrefab` handler), so they get injected too. Selling has no dialog: Interact on the customer at the register calls `ICheckout.ServerOffer` (`CheckoutService`, host; `[Command]` from clients), which checks stock and has the `Checkout Counter` scene NetworkBehaviour lay out the goods (`ProductConfig.ShelfModel`, `Goods Anchor`) and the payment split into bill stacks by `CheckoutConfig.Denominations` (1/5/10/50/100, largest first, `Money Anchor`), all flying in from the customer through `ItemAnimator.FlyInto`. Interact on the money (trigger on the counter root, layer 15, enabled only while money lies there) calls `ServerTake` → `ICustomerService.TrySell`; `RpcClear` flies the bills into the collector's camera and the goods back to the customer. If the customer leaves first, the money returns to them.
- **Shooting range:** `RangeLayout` (`Shooting Range` in `Demo`) lists the `ShootingLane` scene NetworkBehaviours. Each lane has a stand point, a `ShootingTarget` (Akila `IOnHit`) and a world display, and syncs occupied / session end / hits. `ShootingRange` (`IShootingRange`) reserves lanes, runs sessions and simulates visitor shots on the host. `CustomerDirector` turns some spawns (`RangeConfig.VisitorChance`) into range visitors: lane fee + ammo through the same sale dialog, then GoingToLane, Shooting (pistol pose via the Pistol animator layer), Leaving. Player hits count only for the shooter's own local player (`[Command]` from clients).
- **Game day:** `DayNetworkState` (scene NetworkBehaviour) syncs the day number, phase (Open, Closing, Summary), closing time and the day's income, expenses, sales and rentals. Each day starts in Preparing (stock, deliveries, no customers); `DayCycle` (host) opens it when a player presses Interact on the `Open Shop Sign` (`ShopOpenSign`, `IDayCommands.OpenShop`, `[Command]` on clients). The HUD shows an in-game clock from `DayConfig.OpeningHour` (10:00) to `ClosingHour` (16:00) over `OpenDuration` (`DayConfig.ClockAt`); after closing hour `IsAcceptingCustomers` is false and no one new comes, and only then can a player close the shop by pressing the sign again (`IDayCommands.CloseShop`, `CanCloseShop` is false before closing hour), which calls `ICustomerService.CloseShop()`: waiting and arriving customers leave, shooters finish their session. Once no customers remain it switches to Summary. `DaySummaryPresenter` fades the `Screen Fade` overlay (canvas order 90, `ScreenFadeView`) to black, then opens the summary (nested canvas order 100) and `DaySummaryView.Reveal` staggers its `CanvasGroup`s in with PrimeTween while income / expenses / profit count up (timings in `DayConfig`). Only the host gets the Next day button; when the phase leaves Summary every peer closes it, `LocalPlayerSpawner` moves its own local player to a Mirror `NetworkStartPosition` (by netId) while the screen is black, and the overlay fades back in. Sales are recorded in `CustomerDirector.TrySell`, purchases in `ShopNetworkState.ServerPurchase`.
- **Upgrades:** `UpgradeConfig` SOs (price, prerequisite `Requires`, optional `StorageBonus`) are listed in `UpgradeCatalog`. `UpgradeNetworkState` (`IUnlocks`, `IUpgradeCommands`) keeps a host-authoritative `SyncList` of owned upgrade indices. `ProductConfig.RequiredUpgrade` and `ShootingLane.RequiredUpgrade` gate content: purchase validation on the host, customer request picking, lane reservation, and the terminal shows them as locked. Upgrades are bought on the terminal's Upgrades tab (`UpgradesPresenter`) and count as day expenses. The terminal (`Supplier Catalog`, 1500×980) has Weapons / Ammo / Upgrades tabs (`CatalogTab`); every day `DayCycle.PrepareDay` calls `ISupplierPricing.ServerRollPrices` (`ShopNetworkState`, `SupplierPricingConfig`): some products get a sale or a price rise for the day, synced as a `SyncDictionary` of percents, applied in `GetPurchaseCost` and shown on the card (struck-through base price + coloured badge).
- **Saves:** `JsonSaveStorage` (root scope, `persistentDataPath/save.json`, `JsonUtility`) holds a `SaveData` DTO: completed days, money, stock and owned upgrades by asset name. `StartingState` (game scope) reads it only on the host (`NetworkServer.active`) and feeds `Wallet`, `Warehouse`, `UpgradeNetworkState` and `DayCycle`; otherwise it uses `EconomyConfig` defaults. `ProgressSaver` autosaves when a day reaches Summary. The main menu shows "Continue: Day N" and has a New Game button that deletes the save. If you press Play straight from `Demo`, the save is ignored, because the server is not running yet when the scope is built.
- **Balance** targets about 30 minutes (7–8 days of 4 min). Tune it in `EconomyConfig`, `CustomerConfig`, `RangeConfig`, `DayConfig`, the product SOs and the upgrade prices.
- Akila HUD (pause, ammo, hitmarker) is spawned by `Game Manager` through its `uIManager` field, which `Demo` points at Pro's `HUD Variant`.
- `Demo` uses Akila Pro's `Game Manager Variant` with `GameModer` / `GameModerUI` removed (no deathmatch) and `NetworkStartPosition` on the spawn points.

Vendor patches: Mirror `NetworkManager.StopServer/StopClient` only move a **root** NetworkManager out of DDOL (ours is parented to the root scope). Akila Pro `NetworkActor` null-guards `GameModer.Instance`. `InteractionsManager` ignores interactables with an empty prompt and shows the keyboard binding by its physical key name (`InputControlPath.ToHumanReadableString`), so a non-English OS layout does not turn F into a local letter. `PauseMenu` ignores Esc while input is locked. `SettingsPresetShared.SetGlobalVolume` drives `AudioListener.volume` (master), `SetSoundVolume` sets Akila's `FPSFrameworkSettings.globalAudioVolume` (Akila audio and `ShotEffects`), `SetMusicVolume` sets the new `FPSFrameworkSettings.musicVolume` that `MusicPlayer` applies every tick (new methods are appended at the end of the class because the preset inspector stores functions by index); the Audio section of `Settings Menu.prefab` has Global, Sound and Music sliders and `SettingApplier` applies volume options on every slider change even when `SettingsManager.autoApply` is off. `AutoLeaveSession` stops the session and lets Mirror load the offline scene. `NetworkProjectile.DoHit` passes the shooter (not the hit object) as `sourcePlayer` to `Firearm.InvokeHitCallbacks`, so `HitInfo.sourcePlayer` is correct for `IOnHit*` receivers. Scene `NetworkBehaviour`s stay disabled in a player build until Mirror spawns them, so their `netIdentity` is null and `isServer` throws: plain C# code must check them with `IsSpawnedOnServer()` (`Network/NetworkBehaviourExtensions`). `Inventory.Update` clamps `currentItemIndex` to the item count. `NetworkDoor` uses the fully qualified `Akila.FPSFramework.Door`, because third-party assets in `Assembly-CSharp` (e.g. `Tokyo_Street`) declare a global `Door` that would otherwise shadow it.

`VContainerSettings.DisableScriptModifier = true` is required: otherwise VContainer overwrites every new `*LifetimeScope.cs` file with its template.

## Conventions

- Always keep `.meta` files paired with their assets (create/move/delete them together) — GUIDs back all scene/prefab references.
- `Library/`, `Temp/`, `Logs/`, `UserSettings/` are generated; don't edit.
- Play Mode tests driven through the Unity CLI need **Run In Background** (or auto-tick). Otherwise an unfocused Editor barely ticks frames and UniTask awaits and scene loads stall. The project keeps Run In Background off.
- **Feedback loop:** `ShopFeed` (NetworkBehaviour on `DayNetworkState`, `IShopFeed` on the host → `ClientRpc` → `IShopFeedEvents`) drives `NotificationPresenter` / `NotificationView` (top-right toasts) and `WorldPopupSpawner` (floating `+$` text, `FeedbackConfig.PopupPrefab`). Customers show a patience bar (`ServerStartPatience`), wait at an empty stand in `Searching` (`CustomerConfig.SearchPatience`) with the product icon, tip for fast service (`TipWindow`, `MaxTipShare`). Stands have a markup (Interact without a box cycles it, `StoreConfig.MarkupStep/MaxMarkup`; above 0 customers may refuse, below 0 may take one more) and an info label with OUT OF STOCK. Purchases are delivered by a courier (`StoreConfig.CourierPrefab`, a `Customer` in `Delivering`). Boxes can be thrown (T, `StoreConfig.ThrowKey`). `DayEventCatalog` picks a `DayEventConfig` per day (demand, purchase discount, lane fee, visitors, spawn rate). A player's first hit on a free lane starts a timed challenge with a per-lane record (`RangeConfig.ChallengeDuration`).
- **Storage racks:** `StorageRack` (plain MonoBehaviour + `IInteractable`, `Prefabs/Store/Storage Rack.prefab`, listed in `StoreLayout.StorageRacks`, injected by the build callback) has `StorageSlot`s, each with an optional `RequiredUpgrade`: 6 open slots, +4 with Storage1, +5 with Storage2 (15 on three shelves). Interact while carrying a box sends `DeliveryBox.CmdStore(rackIndex)`: the host picks a free slot (no resting box within `StoreConfig.StorageSlotRadius`, checked by `CarryService.IsRestingNear` on synced rest positions) and sets the box rest pose there, so every peer plays the usual `ItemAnimator.Land`. Boxes are taken back with a normal pickup. The `Marker - Storage` world marker (child of the rack, `WorldMarkerSet.Storage`) shows while the local player carries a box. `Warehouse` capacity is counted in boxes (`ProductConfig.BoxesFor` = units rounded up by `UnitsPerBox`): `EconomyConfig.WarehouseCapacity` 6, Storage1 +4, Storage2 +5, matching the rack slots; the terminal blocks orders that need more box slots than are free.
- **HUD helpers:** `HudConfig` drives `HintsView` / `HintsPresenter` (bottom-centre control hints: carrying a box, holding a weapon, default; hidden while input is locked) and `SaveIndicatorView` / `SaveIndicatorPresenter` (bottom-left spinner "Saving..." then "Game saved", host only, on `ISaveEvents.Saved` raised by `ProgressSaver`). Boxes cannot be picked up while the local player holds a weapon (`IPlayerHands.IsHoldingWeapon`: Akila `currentItemIndex >= 0`); the box prompt says `StoreConfig.WeaponBlocksCarryPrompt` instead.
- **Rental weapons:** `RentalWeaponCatalog` / `RentalWeaponConfig` (networked Akila `InventoryItem` + display model in `Prefabs/Rentals`). Two scene `RentalWeaponHolder`s (`RentalStations` in `GameLifetimeScope`): `Rental Rack` on the back wall behind the counter and `Rental Counter` at the register. Each slot is its own `RentalSlot` (collider on layer 15) that forwards to the holder: Interact on an occupied slot takes that weapon into the local player's Akila inventory, and an empty slot shows a translucent orange `FeedbackConfig.GhostMaterial` (`ShooterShop/Placement Ghost` shader) copy of the held rental weapon and puts it there; the weapon under the cursor gets the outline material appended (`MaterialOutline`). Taking and putting go through `IPlayerHands` / `AkilaPlayerHands` (`TargetRpc` gives the item). With `RangeConfig.RequiresRentalWeapon`, a range visitor pays, goes to the counter (`GoingToHandout` → `WaitingForWeapon`, `RentalWaitPatience`), takes a weapon from it, shoots, then walks back (`ReturningWeapon`) and puts it on the counter itself, waiting while the counter is full.
- **Violence:** `Customer` implements Akila `IOnHitInChildren`. Its root capsule (layer 15) is a trigger used only for interaction; bullets hit the ragdoll bones copied from `Player Network` (11 `Rigidbody` + `CharacterJoint` + collider + Akila `CustomDecal` with `Blood Impact`, layer Default because Akila `hittableLayers` exclude 15, non-trigger because projectiles ignore triggers). Only the shooter's own client reports a hit with direction and point (`[Command]`); `CustomerDirector` (`ICustomerDamage`) kills after `CustomerConfig.HitsToKill`: items go back, a held rental weapon goes to the counter, `ServerDie` → `RpcDie` turns on `CustomerRagdoll` on every peer with `DeathImpulse` at the hit point, after `CorpseSinkDelay` it freezes and sinks the `Model` under the floor, then the server despawns it; every other customer flees faster and no one spawns for `PanicDuration`. Killing a customer fines the shop `EconomyConfig.KillFine` through `IFines` (`Bank`, `IWallet.Charge` may go below zero); whenever the balance drops to zero or below, `Bank` tops it up to `LoanAmount` as an automatic loan. Pedestrians are not fined. Couriers ignore hits.
- **Customer appearances:** the `Customer` prefab has no model. `CustomerAppearanceCatalog` (`Configs/`) lists 106 `CustomerAppearance` prefabs (`Prefabs/Customers/Appearances`) built from Citizens PRO adults by **Shooter Shop > Customers > Build Appearances** (`CustomerAppearanceBuilder`): Citizens models and idle/walk/run clips are imported as Humanoid, the Mixamo stance clips are converted too, `CustomerHumanoid.controller` (MoveX/MoveY locomotion + `Weapon` layer) with per-gait override controllers, and an auto-built humanoid ragdoll (11 bodies, Akila `CustomDecal` blood) plus `CustomerRagdoll`. The server picks `_appearanceIndex` (SyncVar) in `ServerInitialize*`, every peer instantiates it in `Customer.BuildAppearance` and attaches the display model of the visitor's actual rental weapon to the right hand. Walk/run blending uses `WalkClipSpeed`. Range shooting uses the Mixamo clips in `Art/Animations/Customers` (`Pistol Idle`, `Rifle Aiming Idle`, `Firing Rifle`, Humanoid, the pistol and fire clips copy the rifle clip's avatar) on the `Weapon` layer (body + arms mask); `RentalWeaponConfig.Pose` (Pistol / Rifle) picks the state, `RpcFire` plays `Rifle Fire` for rifles and `ShotEffects` (`ShotEffectsConfig`, everything spawned through Akila's `PoolManager.Get(prefab, releaseAfter)`: muzzle flash + smoke, a fading `LineRenderer` tracer to the aim point with scatter, 3D `RentalWeaponConfig.FireSound` at `MuzzleDistance` along the held model), and `CustomerRegistry.PostLateTick` → `AppearanceBody.AlignWeapon` keeps the held model on the right hand pointing at the synced lane target (`ServerAimAt`, the host also turns the shooter to it every tick) or along the body, placed by the weapon's own `RentalWeaponConfig.HandOffset` / `HandRotation`.
- **Intro and boss visits:** `IntroConfig.Visits` (day, dialog lines, `StartsAmbush`) drive the `ShopBoss` scene NetworkBehaviour (`IInteractable`, `IntroConfig.BossAppearance`, SyncVar present / leaving, hidden instead of destroyed). `IntroDirector` (host) shows him at `IntroLayout.BossSpawn` in the Preparing phase of a visit day and sets `IntroNetworkState.PendingVisit`; Interact opens `DialogView` / `IntroPresenter` (input lock), the last line calls `IIntroCommands.ServerFinish` (`[Command]` on clients), the boss walks to `BossExit` and hides. Day 1 is the intro: on a new game (`StartingState.CompletedDays == 0`) the shop starts dark and locked (`IntroLayout` lists the `GunShop/Lights` and the entrance `IntroDoor`s `Prop_Gate (3)/(4)`), finishing it sets `IntroPhase.Completed` and every peer flickers the lights back to their authored intensities and swings the doors open; with a save the phase is Skipped (instant). Day 4 starts the street ambush. `DayCycle` refuses to open the shop while a visit is pending or an ambush is active.
- **Street ambush:** `IRaid.ServerStartAmbush` (`RaidDirector`) spawns `RaidConfig.AmbushCount` gunmen at `AmbushLayout` points across the street; ambushers (`Raider.IsAmbusher`) alternate bursts (`AmbushBurstTime`) with dashes to random spots within `AmbushWanderRadius` of their point, shoot players within `AmbushAttackRange` and never flee. They show a red `▼` screen label (`RaidConfig.MarkerStyle`). `AmbushNetworkState` (`IAmbushState`, on `DayNetworkState`) syncs active / killed / total for `AmbushHudView` / `AmbushHudPresenter` ("Bandits killed: k / n"); when all are dead the host pays `AmbushReward`.
- **Mafia raid:** `DayEventConfig.HasRaid` marks a raid day; `DayEventCatalog` has `Scheduled` events that always fire on a given day (the `MafiaRaid` event on day 2) and are excluded from random picks. `RaidDirector` (host, `IRaid`, `IRaidDamage`, `RaidConfig`) waits `StartDelay` after opening, evacuates customers (`ICustomerService.Evacuate`), spawns `Thieves` + `Gunmen` `Raider`s (`Prefabs/Raids`, NetworkBehaviour, `AppearanceBody` look from `RaidConfig.Appearances`, rental weapon display models) at `ShopLayout.Exit`. Thieves `ServerTake` whole stands up to `CarryCapacity` and run back to the exit, where the loot is removed from `Warehouse`; gunmen chase the nearest player and shoot when in `AttackRange` with line of sight (`SightMask`), dealing `Damage` with `HitChance` (falling off with distance to `HitChanceAtRange`; misses fire at a point `MissOffset` away so the tracer visibly misses) through the Akila fork interface `IServerDamageable` (implemented by Pro `NetworkDamageable`). When no thief is left, or the shop closes, everyone flees. Player hits work like customers (`IOnHitInChildren`, `HitsToKill`, ragdoll + sink); a killed raider pays `Bounty` and returns his loot to the stands (or a box). `DayCycle` does not reach Summary while a raid is active. `RaiderRegistry` ticks locomotion and weapon alignment on every peer.
- **Street pedestrians:** `PedestrianDirector` (host) spawns `PedestrianConfig.Count` `Pedestrian`s (`Prefabs/Street`, NetworkBehaviour + `IInteractable`, random `CustomerAppearanceCatalog` look via the shared `AppearanceBody`, which `Customer` uses too) that walk between `StreetLayout` waypoints (`Street` in `Demo`) and idle for `IdleTime`. Interact sends `CmdTalk`: the pedestrian stops for `TalkPause`, turns to the speaker and every peer shows a random `Replies` line on the screen label layer. They implement `IOnHitInChildren` like customers: any hit (`IPedestrianDamage` = `PedestrianDirector`) makes every pedestrian panic (faster, no idling, `PanicReplies` shouts) for `PanicDuration`, `HitsToKill` hits ragdoll and sink the body, and a replacement spawns after `RespawnDelay`. Only waypoints reachable over the NavMesh are kept (the street NavMesh volume now covers the whole street and carves the houses).
- **Menu camera tour:** `Main Menu` has `Camera Tour` (`MenuCameraTour`: the menu `Camera` plus `MenuCameraShot`s, each a From → To pair of child points with an optional duration) and `Screen Fade` (overlay canvas at sorting order -100, under the menu HUD, `ScreenFadeView`). `MenuCameraTourPlayer` (entry point in `MenuLifetimeScope`, `MenuCameraTourConfig`) loops the shots: slow eased move, fade to black before the end, hold, cut to the next shot and fade in.
- **Music:** `MusicPlayer` (`IMusicPlayer`, root `ProjectLifetimeScope`, `Configs/MusicConfig`) owns two DontDestroyOnLoad `AudioSource`s and crossfades tracks of the `Menu` / `Gameplay` playlists (shuffle, auto-next before a track ends). Each scene scope registers a `MusicCue` entry point with its `MusicPlaylist`. Reuse Akila's `PoolManager` for any pooled effects instead of writing a new pool.
