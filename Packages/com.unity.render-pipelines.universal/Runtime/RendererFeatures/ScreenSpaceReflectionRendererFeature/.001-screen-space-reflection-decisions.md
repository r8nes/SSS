# Screen Space Reflection

SSR uses one hierarchical Hi-Z tracing path implemented in `ScreenSpaceReflection.compute`. Linear tracing, a raster SSR implementation, a separate resolve pass and a separate hit-buffer pass are not part of the implementation.

The compute pass evaluates receiver eligibility, ray setup, hierarchical traversal, mip-0 hit acceptance, previous-color reprojection and radiance lookup. A current-frame Hi-Z hit is never rejected by previous-frame geometry. Previous color history is used only as the radiance source required by the pre-opaque Forward+ integration. Motion vectors, when available, adjust only the previous-color lookup coordinates.

The compute result is RGBA16F premultiplied reflection data: RGB contains reflected radiance multiplied by confidence and alpha contains confidence. Misses are zero. Half- and quarter-resolution reconstruction are compute kernels in the same shader.

SSR has no reflection depth history, target-depth-history pass, temporal accumulation or temporal reflection history. It is disabled for XR cameras, MSAA camera targets, orthographic cameras, compatibility mode and non-2D camera targets.

Rough reflections use a receiver-space Gaussian result pyramid. RGB and confidence are filtered together, then material lighting decodes premultiplied radiance and blends SSR with the existing reflection hierarchy. The renderer-owned `ColorPyramidGenerator` is the only Gaussian pyramid implementation used by SSR and renderer color pyramids.
